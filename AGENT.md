## Repository Overview

Monorepo of RimWorld mods targeting RimWorld 1.6 (.NET Framework 4.7.2, C# latest). All mods share a `Utility` library and follow the same architectural patterns.

**Mods:**
- **Rimsonable** — Core gameplay overhaul with individually toggleable features
- **Rimfined** — QoL and UI improvements
- **AnimalHaulExtended** — Extended animal hauling mechanics
- **EntropyOverflow** — Psychic resonance system (early development)
- **Healthy Sleep** — Sleep and circadian overhaul
- **RemedialAlgorithms** — Performance optimizations
- **Profiler** — Custom performance diagnostics tool

## Build & Run

Each mod is an independent project within the parent solution (`RimWorld Mods.slnx`). Build from the repo root or from any mod's `Source/` directory.

```bash
# Build a specific mod (runs Distribute, Deploy, ILRepack automatically)
dotnet build Rimsonable/Source/Rimsonable.csproj
dotnet build HealthySleep/Source/HealthySleep.csproj

# Build a compatibility module
dotnet build Rimsonable/Source.CE/Rimsonable.CE.csproj

# Clean a mod's output
dotnet clean Rimsonable/Source/Rimsonable.csproj

# Launch RimWorld for testing (generated by build)
Rimsonable/LaunchRimWorld.bat
HealthySleep/LaunchRimWorld.bat
```

Build pipeline per mod:
1. Copies assets from `Public/` -> `Dist/`
2. Expands `{{Token}}` placeholders in `Template/About.xml`
3. Processes translation XMLs from `Languages/` -> `Dist/Shared/Languages/`
4. ILRepacks the assembly + NuGet dependencies into `Dist/1.6/Assemblies/`
5. Creates a Windows junction from `Dist/` into the game's `Mods/` folder
6. Generates `LaunchRimWorld.bat` (runs game with `-savedatafolder=SaveData`)

There are no tests or linters configured.

## Shared Infrastructure (`Utility/`)

All mods reference `Utility/Utility.csproj`. Key components:

**`FeatureSettings<T>`** — Base class for mod settings. Handles Harmony patch registration/unpatching, settings UI rendering via `Listing_Standard`, and persistence via `Scribe_Values` (camelCase keys).

**`[Feature]` attribute** — Applied to `Features` enum fields. Declares `ModDependencies`, `ModIncompatibilities`, and `DefaultEnabled`. The base class discovers patches and settings entries via reflection.

**`[Translation]` attribute** — Maps C# members to RimWorld translation XML keys. Applied at field or type level (type-level with `ImplicitMembers = true` auto-derives keys from member names).

**`Logger`** — Debug logger with a per-mod prefix. Enabled by default in `#if DEBUG`. Methods: `Message()`, `Warning(once:)`, `Error(once:)`.

**`Flexbox`** — CSS-flexbox-inspired UI layout that partitions `Rect` into child subrects using `fr` and `px` sizing.

**MSBuild Tasks** (`Utility/Tasks/`): `BuildXml`, `ProcessTranslations`, `CreateLink` — invoked automatically during build.

## Architecture Patterns

### Feature System

Most mods use a `[Flags]` enum plus `Settings : FeatureSettings<Features>` to control optional systems. Example:

```csharp
[FeaturesEnum(defaultEnabled: true)]
public enum Features : ulong {
    [Feature(ModDependencies = [ModIds.SomeMod])]
    MyFeature = 1ul << 0,
}
```

Patches are registered in the `Settings` static constructor:

```csharp
static Settings() {
    AddFeaturePatches(Features.MyFeature, typeof(MyFeaturePatch));
}
```

Standalone mods can still use the same pattern even if they currently expose only one top-level toggle, such as `Healthy Sleep`'s `DeepSleep` setting.

### Harmony Patches

Attribute-based declaration, grouped in `Patches/` (one file per feature or system):

```csharp
[HarmonyPatch(typeof(TargetClass), "MethodName")]
private static bool MethodName_Prefix(ref int __result) { ... }
```

Compatibility patches (CE, VEF) are registered in `[StaticConstructorOnStartup]` `Initializer` classes inside their respective `Source.CE/` / `Source.VEF/` assemblies.

### Mod Entry Point

```csharp
public class Mod : Verse.Mod {
    public Mod(ModContentPack content) : base(content) {
        Settings.Default = GetSettings<Settings>();
        LongEventHandler.QueueLongEvent(() => Settings.Default.Apply(), ...);
    }
    public override void DoSettingsWindowContents(Rect inRect) =>
        Settings.Default.DrawContents(inRect);
    public override string SettingsCategory() => ThisAssembly.Info.Title;
}
```

### Assembly Metadata

Use `ThisAssembly.Info.*` (title, version, etc.) and `ThisAssembly.Project.*` — generated by the `ThisAssembly` source generator from project properties.

### Distribution Layout

| Directory    | Purpose                                                                   |
| ------------ | ------------------------------------------------------------------------- |
| `Public/`    | Source assets (Defs XML, LoadFolders.xml, About art)                      |
| `Template/`  | `About.xml` / `ModsConfig.xml` templates with `{{Token}}` placeholders    |
| `Languages/` | Translation source XMLs (processed by `ProcessTranslations` task)         |
| `Dist/`      | Build output — mirrors RimWorld mod folder structure; symlinked into game |

## Namespaces & Conventions

- Root namespace: `TrueMogician.RimWorld.<ModName>`
- Compatibility assemblies append `.CE`, `.VEF`, `.VF`
- Shared library: `TrueMogician.RimWorld.Utility`
- `ModIds.cs` — string constants for mod package IDs used in dependency/incompatibility declarations
- Settings persistence uses camelCase `Scribe_Values` keys
- Translation keys follow `<ModName>.Settings.<Path>` and are resolved via `[Translation]`

## Key Files Per Mod

- `Source/Mod.cs` — Entry point
- `Source/Settings.cs` — `Features` enum + `Settings : FeatureSettings<Features>`
- `Source/Patches/` — Harmony patch classes for the mod's systems
- `Source/Components/` — Runtime components and stateful systems, when used
- `Source/Static/ModIds.cs` — Mod ID constants for dependency/incompatibility declarations
- `Public/LoadFolders.xml` — Conditional assembly loading for compatibility modules
- `Template/About.xml` — Mod metadata template
- `TODO.md` — Feature backlog and rollout plan (check before adding features to avoid duplication)

## Knowledge Base (`Knowledge Base/`)

This directory is Git-ignored but safe to explore freely. It is the primary reference for RimWorld modding:

- `Knowledge Base/Decompiled` and `Knowledge Base/Definition` — The most important reference. Use it to understand vanilla game logic before patching, look up method signatures, and verify API usage for RimWorld 1.6.
- `Knowledge Base/Mod Repository` — Reference implementations from mods like Combat Extended and Vehicle Framework. Useful for understanding compatibility patterns.
- `Knowledge Base/Steam Workshop` — All locally installed mods are accessible here. Useful for studying how other mods solve similar problems.

Always consult the decompiled source when implementing patches or working with game types — it is authoritative for the 1.6 API.
